# Database — Stage 8/11/12/13 back-end: SQL schema, CRUDL DAOs, migrations, DB<->JSON/XML io, REST, SOAP, WSDL, gRPC impls

**Pipeline role:** Stage 8 (SQL schema, CRUDL, migrations, DbIo) + Stage 11 (SOAP, WSDL) + Stage 12 (REST) + Stage 13 (gRPC service impl). Everything is generated from the `Message` objects produced upstream (LexicalAnalizer/MessageCreator).
**Entry points:** every adapter has the same shape `XxxAdapter(messages=msgFactory.messages, dest=testDestination).Process()`; called from `main.py`. `Process()` returns `None` (logs a count; not a real error object). Constructors take only `(messages, dest)`.
**Inputs → Outputs:** consume the full `messages` list (each `Message` has `.name`, `.md5Hash`, `.tableName`, `.visibility`, `.isEnum`, `.variables`; each variable has `.name`, `.type` (a `[kind, refName]` pair — `"ID"` means composed ref), `.modifiers`, `.typeMap`). Every adapter skips enums and messages with no `tableName` (SqlAdapter emits a one-line note instead). Output roots under `<dest>`:
  - SqlAdapter → `<dest>/database/` (`.sql`)
  - WsdlAdapter → `<dest>/wsdl/` (`.wsdl`)
  - all C++ header adapters → `<dest>/generated/cpp/<sub>/` where `<sub>` = `db`, `migrate`, `dbio`, `rest`, `soap`, `grpc`

## Files
- `model.py` — **the shared schema model; central, read first.** `type_registry(messages)` maps each declared type name → `{"kind": "enum"|"table"|"message", "msg": <Message>}` (table = has `tableName`, message = composed but table-less). `analyze(msg, types)` → `(columns, notes)`: scalar field → bindable `Column` (SQLite type via `_SCALARS`; `ID_*` → INTEGER PRIMARY KEY; `REQUIRED`→NOT NULL, `UNIQUE`→UNIQUE); composed field to an **enum** → bindable INTEGER column; to a **table** message → non-bindable `fk_table` INTEGER column holding the child's PK; to a **table-less** message → `_flatten()` inlines its scalar/enum sub-fields as prefixed columns `parent_sub` bound through the parent accessor chain (`Column.embed` is a LIST of accessors, e.g. `["path","start"]` for 2-level nesting; `child_accessor` is the final step; C++ `x.path().start().city()`). `_flatten()` recurses when a sub-field is itself composed to ANOTHER table-less message, compounding the column-name prefix and the embed chain (`prefix=False` skips both, for one repetition's worth of unprefixed/unbound columns — see `RepeatedComposedField` below). Map fields are deferred here (emit a `note`) and handled by `map_fields()`; repeated fields likewise by `repeated_fields()`. `Column` carries C++ codegen helpers: `getter()`, `set_stmt()`, `sql_def()`. `MapField` → child table `<table>__<field>` (owner, key, value); `RepeatedField` → child table `<table>__<field>` (owner, ordinal, value), with `fk_target` set when it's a repeated composed→table field (1-to-many via link table storing the child PK); `RepeatedComposedField` → child table `<table>__<field>` (owner, ordinal, one column per the target's own flattened scalar/enum fields, unprefixed) when the repeated field's target has no table of its own. All three support embed-nested variants (map/repeated/repeated-composed reached through a flattened table-less composed field, table name `<table>__<embed>_<field>`) — that embed stays a single-level string (only `_flatten()`'s own `embed_path` is a multi-level chain). `_HIDDEN_PREFIXES` (ID_/STATUS_/ERROR_/ORIGINATOR) are front-end-injected fields skipped when flattening. `create_table_sql()` = compact one-line CREATE TABLE for embedding in C++. `pagination_default(msg)` → the `paginationSize` of the first field carrying the `PAGINATION` modifier, or `None`; drives the paginated `list(offset, limit)` DAO overload's REST default.
- `SqlAdapter.py` — Stage 8 schema. Renders `templates/table.sql.tmpl` per message → `<name>_<hash>_table.sql`. Emits the main CREATE TABLE plus one child table per map (owner,key,value) and per repeated scalar (owner,ordinal,value). Validated against vendored SQLite in tests.
- `CrudlAdapter.py` — **largest/most important.** Header-only DAO `<name>_<hash>_crudl.h` (`::harpia::db::<name>_dao`) over vendored sqlite3: create/read/update/remove/list (+ a paginated `list(out, offset, limit)` overload, `LIMIT`/`OFFSET` bound via SOCI) + create_table/drop_table. Builds INSERT/SELECT/UPDATE bind & extract lines from `analyze()` columns so SQL matches the schema. Handles: scalar/enum, flattened-embed columns (incl. multi-level nested embed chains), singular FK-to-table columns (child persisted/loaded via the child's own DAO — `_fk_hooks`/`_fk_extract`), map child tables, repeated-scalar child tables, repeated-FK link tables (1-to-many, persists each child via its DAO then links its PK, `_rep_write`/`_rep_read`), and repeated-composed-to-table-less child tables (`_rep_composed_write`/`_rep_composed_read`, one multi-column row per element, no child DAO). Pulls in child-DAO headers via `_fk_includes`. Includes the message's protobuf header `protofiles/<name>_<hash>.pb.h`.
- `MigrationAdapter.py` — Stage 8 migration. `<name>_<hash>_migrate.h` with `migrate_<name>(sqlite3*)`. **Additive only:** ensures table (+child tables) exist and `ALTER TABLE ADD COLUMN` for any non-PK column an older version lacks; records version in `_harpia_schema_version`. No renames/drops/type-changes/data transforms.
- `DbIoAdapter.py` — Stage 8/9/10 bulk io. `<name>_<hash>_dbio.h` composing the CRUDL DAO with the JSON and XML adapters: `export_json`/`import_json` (newline-delimited JSON) and `export_xml`/`import_xml` (`<name>_list` wrapper). Pure template fill (name/hash only).
- `RestAdapter.py` — Stage 12. `<name>_<hash>_rest.h`: registers CRUD routes on a Crow server (`crow::SimpleApp`, via `route_dynamic`) backed by the DAO. GET-list is paginated via `?limit=&offset=` (limit>0 triggers the DAO's paginated overload; the message's `pagination_default()` becomes the default limit when the request omits it). Content negotiation (XML if Content-Type/Accept says "xml", else JSON) reusing JSON+XML adapters. Credential-gated (see gotchas). Template-only fill except `default_limit` (from `pagination_default()`).
- `SoapAdapter.py` — Stage 11. `<name>_<hash>_soap.h`: SOAP envelope endpoint on a Crow server (`crow::SimpleApp`) (get/set/update/delete in Body) using tinyxml2 + XML adapter + DAO. Template-only.
- `WsdlAdapter.py` — Stage 11. Static `<name>_<hash>.wsdl` (WSDL 1.1, document/literal SOAP 1.1) describing the SOAP service. complexType lists only top-level **bindable** scalar/enum fields (via `analyze()` + `_XSD` kind→XSD map); nested/repeated/map handled by the runtime, not expanded. No C++.
- `GrpcServiceAdapter.py` — Stage 13. `<name>_<hash>_grpc.h`: concrete impl of the service skeleton emitted by ProtoFile/GrpcCompiler; RPCs call the DAO (push→create, pullByID→read, streamSrc→list [paginated via the request's `offset`/`limit` fields when `limit>0`, else unbounded], heartBeat→echo). Data RPCs credential-gated via call metadata. Template-only.
- `templates/` — one template per adapter, filled with `str.format` (literal C++ braces are `{{`/`}}`): `table.sql.tmpl`, `crudl.h.tmpl`, `migrate.h.tmpl`, `dbio.h.tmpl`, `rest.h.tmpl`, `soap.h.tmpl`, `grpc_service.h.tmpl` (all C++/SQL), and `wsdl.tmpl` (XML). Loaded once at import via `Util.util.loadTemplate(__file__, name)`.

## Key facts / gotchas
- **Output filenames are md5-hash-qualified: `<name>_<md5Hash>_<suffix>`** (`_table.sql`, `_crudl.h`, `_migrate.h`, `_dbio.h`, `_rest.h`, `_soap.h`, `_grpc.h`, `.wsdl`). Include-guards and pb-header refs also embed `<name>_<hash>`. Relevant to the upcoming multi-root feature: the hash disambiguates same-named messages, but only where the hash is applied — filenames and guards are safe.
- **SQL/C++ identifiers are NOT hash-qualified:** `tableName`, child-table names (`<table>__<field>`), the C++ `<name>_dao` class, `authorized_<name>`, and (per the sibling ProtoFile stage) **service proto MESSAGE names** are plain `name` — a dup-def / collision risk across roots that the multi-root work must address.
- **Credential/auth is currently the message name + hash as literals, not a real Stage 5 credential:** REST checks `X-User == "<name>" && X-Pswd == "<hash>"` (401 otherwise); SOAP gates the same way; gRPC checks `x-user`/`x-pswd` call metadata (UNAUTHENTICATED on mismatch). heartBeat/gRPC stays open. So the "access credential" baked in is just `{name}`/`{hash}`.
- FK/map/repeated/embed persistence design lives entirely in `model.py`; SqlAdapter, CrudlAdapter, MigrationAdapter, WsdlAdapter all re-derive columns from `analyze()` (+`map_fields`/`repeated_fields`) so schema, DAO SQL, migration and WSDL never drift. RestAdapter/SoapAdapter/DbIoAdapter/GrpcServiceAdapter do NOT call `analyze()` — they only substitute name/hash and delegate to the DAO + JSON/XML adapters at C++ level.
- Deferred (noted in output, not yet implemented): non-additive (rename/drop/type-change) version-transform/data migrations. (Repeated fields whose target is table-less, composed fields nested inside an embedded message whose own target is ALSO table-less, and composed fields nested inside an embedded message whose OWN target is a table-bearing message — an FK found inside an embed, via `_flatten()`'s `kind == "table"` branch and `Column.mutable_ptr()`/`has_expr()` in `CrudlAdapter` — are all implemented; see `RepeatedComposedField` and `_flatten()`'s recursion above.)
- `analyze` deliberately falls back to a deferred plain-INTEGER FK when `types` is missing/unknown — always pass `self.types` (adapters do).

## Touchpoints
- Called by: `main.py` (order: GrpcServiceAdapter, then Sql, Crudl, Migration, DbIo, Rest, Soap, Wsdl) and `run_pipeline.py`/`run_harpia.sh`.
- Depends on: `Database.model`; `Message` objects from `LexicalAnalizer`/`Message` (MessageCreator); `Logger.logger`, `Util.util.loadTemplate`; `Errors.Error` (imported by SqlAdapter but unused). Generated C++ depends on vendored sqlite3 (`third_party/sqlite`), Crow + standalone asio (`third_party/crow`, `third_party/asio`), tinyxml2, protobuf/gRPC, and the sibling JSON/XML adapters' generated headers.
