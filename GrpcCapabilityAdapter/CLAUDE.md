# GrpcCapabilityAdapter — gRPC capability handshake (gRPC slice)

**Pipeline role:** Stage 13 (gRPC). Ships a hand-written client runtime and emits ONE whole-project server implementation advertising every message type the generated peer knows about, so a caller can ask "does this peer understand type X" via a real RPC instead of finding out by having a push/pull/stream call fail (or, on a transport with no compile-time backstop, silently misroute). Design: a per-peer advertised *set* of message-type names, checked by membership, not an ordinal version number — shipped as part of the message-versioning effort's capability handshake (2026-08-23). Sibling adapters `HttpCapabilityAdapter/` (REST+SOAP) and `ZmqCapabilityAdapter/` (ZMQ) round out the transport-specific slices — see their own `CLAUDE.md`s and `Capability/CLAUDE.md` for what's shared across all three.
**Entry points (from main.py):** `GrpcCapabilityAdapter(messages=msgFactory.messages, dest=testDestination, rootHash=rootFile.getHash()).Process()`. Returns `None` or an `Error` (non-fatal; main.py logs it, matching every other adapter).
**Inputs → Outputs:** consumes the full `messages` list (via `Capability.capability_common.message_type_names` — no per-message dest, unlike every other Stage 13 adapter). Emits `<dest>/generated/cpp/capability/capabilities_<rootHash>_grpc.h` (server impl) and copies both the gRPC-specific `harpia_capability.h` runtime and the shared `harpia_capability_dispatch.h` into the same directory (mirrors `XmlAdapter`'s `harpia_xml.h` split). The static `Assets/proto/protofiles/capabilities_service.proto` is copied by `Util.util.copyBasicProtos` (alongside `errorCode.proto`/`heartBeat.proto`) — **not** emitted by this adapter, since the wire contract (`capabilities_Request`/`capabilities_Response`/`capabilities_Service`) is fixed, not schema-derived, and is shared verbatim by the HTTP and ZMQ slices too (their message payloads, not their transports).

## Files
- `GrpcCapabilityAdapter.py` — `Process()` copies both runtime headers (own + shared dispatch, via `Capability.capability_common`), then renders the template with `Capability.capability_common.message_type_names(messages)` baked in as a `static const std::vector<std::string>`.
- `templates/capabilities_service.h.tmpl` — `harpia::grpc_svc::capabilities_service`, a concrete `::frameworkProtos::capabilities_Service::Service` subclass whose one RPC (`GetCapabilities`) returns the baked-in type list. Register one instance alongside a generated project's other gRPC services (not auto-wired into `server_template`/`client_template` — those are ZMQ-only, and per-message gRPC services aren't auto-registered there either, so this follows the existing precedent of shipping scaffolding the caller wires up themselves).
- `runtime/harpia_capability.h` — hand-written (NOT generated), copied verbatim like `XmlAdapter/runtime/harpia_xml.h`. `negotiate(channel, timeout, on_legacy_peer = noop)` — calls `GetCapabilities` with a real deadline (`grpc::ClientContext::set_deadline`). Any non-OK status (peer never registered the service → `UNIMPLEMENTED`; peer never answers in time → `DEADLINE_EXCEEDED`; any other transport failure) is resolved uniformly to the plan's "legacy peer, no capability set" outcome: `on_legacy_peer()` fires exactly once and the function returns `std::nullopt` — never a hang, never a silently empty set. `Dispatcher` used to live in this same file; it's now `capability/harpia_capability_dispatch.h` (see `Capability/CLAUDE.md`) since it's transport-agnostic and shared by all three slices.

## Key facts / gotchas
- **Whole-project artifact, not per-message** — unlike every other Stage 13 adapter (`GrpcServiceAdapter`, and every proto/JSON/XML/DB adapter), there is exactly ONE `capabilities_<rootHash>_grpc.h` regardless of how many messages the schema declares, because the capability *set* is a property of the generated peer as a whole. Filename is qualified by the **root file's** hash (like every other Stage 13 output), not any one message's, since there's no single message to key it to.
- **`_ALWAYS_VALID_BASENAMES` in `Util.util`** had to gain `"capabilities"` (alongside `TestAdapter`'s existing `"app"`) — `prune_stale_outputs` matches the `<name>_<hash>...` filename convention and would otherwise treat `capabilities_<hash>_{grpc,http,zmq}.h` as orphans every single run (their "name" isn't any live message name) and delete-then-recreate them, defeating `write_if_different`'s mtime stability. One entry covers all three transports' generated filenames since they all share the `capabilities_` prefix.
- **`GetCapabilities` is deliberately ungated** — like `heartBeat`, it carries no `x-user`/`x-pswd` credential check. Advertising *which types exist* isn't itself sensitive the way reading/writing data is; gating it would also block exactly the bootstrapping case (a client that doesn't yet know if it's talking to a legacy peer) the handshake exists to handle gracefully. Same choice made for HTTP's `/capabilities` route and ZMQ's responder.
- **`negotiate()`'s failure handling is deliberately coarse**: any non-OK gRPC status is treated as "legacy peer," not distinguished from a genuine transient network error. This matches the plan's own framing (absence of a capability response, for *any* reason, is one named outcome) rather than inventing finer-grained error taxonomy this slice needs. Same coarse-failure choice in the HTTP and ZMQ `negotiate()`s.
- Pure text emission (template `.format()`) — does not require `protoc` to have run; the emitted header only *compiles* once Stage 7 (`ProtoCompiler`) and Stage 13's `GrpcCompiler` have produced `capabilities_service.pb.h`/`.grpc.pb.h` from the static proto (inside the harpia Docker image). (HTTP/ZMQ only need Stage 7's plain `.pb.h` — no gRPC stub — since neither rides gRPC.)

## Touchpoints
- Called by: `main.py` (step 13, right after `GrpcServiceAdapter`) and `UnitTests/run_pipeline.py`.
- Depends on: `Util.util.loadTemplate`/`write_if_different`/`copy_if_different`, `Logger.logger`, `Capability.capability_common`. Consumes `MessageCreator` messages (name/isEnum only, via the shared helper) and `rootFile.getHash()`. The static proto lives in `Assets/proto/protofiles/capabilities_service.proto`, copied by `Util.util.copyBasicProtos`; compiled by `ProtoFile/ProtoCompiler.py` (globs all `.proto`) and `ProtoFile/GrpcCompiler.py` (globs `*_service.proto`, which this file's name already matches).
