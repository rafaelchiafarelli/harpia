## Decide the `.harpia` opt-in for a database-assigned key

- **Depends on:** nothing. **Deliverable: a decision, recorded in this file
  and in `../../README.md`, plus the lexer/grammar contract for tasks 2–4.**
  No generator code.
- Standing principle: the generator never infers this; the schema says it.
- **Options:**
  1. **Message-level modifier** before `message`, beside `protected`/`open`
     (e.g. `autokey message P { ... } p_table;`). Recommended: per table,
     explicit, same lexer path as the hardening modifiers.
  2. **Project-wide** `project.harpia.yaml` setting — one switch, but hides a
     per-table storage choice outside the schema.
- **Questions to settle with it:** `create` with `HARPIA_ID` already set —
  error or honoured? (recommended: error, one source of truth); the assigned
  key written back into the caller's message (recommended: yes); PG uses
  `GENERATED ... AS IDENTITY`; migration of an existing caller-assigned table
  to auto (recommended: allowed, the column type doesn't change on SQLite;
  PG adds the identity).
- **Docs:** the modifier in `USAGE.md` §3 once decided.

## Decision (Rafael, 2026-11-01)

- **Option 1: `autokey` message-level modifier**, beside `protected`/`open`:
  `autokey message P { ... } p_table;`. Flag only in the front end
  (`Message.is_autokey`); a message without a table carrying it is a
  generation error (nothing to assign a key in).
- **`create()` with `HARPIA_ID` already set (≠ 0) is an error** — one source
  of truth. C++ returns `false`; Python and Java raise `ValueError` /
  `IllegalArgumentException`.
- **The assigned key is written back** into the caller's message: C++
  `create(T& msg)` overload for autokey DAOs (the `const T&` form is not
  generated for them), Python sets it on the object, Java returns the key.
- **SQLite:** `INTEGER PRIMARY KEY` without binding it (rowid alias); read
  back with `last_insert_rowid()` (SOCI `get_last_insert_id`). **PostgreSQL:**
  `GENERATED BY DEFAULT AS IDENTITY`, read back with `RETURNING`.
- **Migration of an existing caller-assigned table to autokey:** allowed;
  SQLite needs no change (the column is already the rowid alias), PG adds the
  identity (`ALTER COLUMN … ADD GENERATED BY DEFAULT AS IDENTITY`, restarted
  past `max(key)`).
