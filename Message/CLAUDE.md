# Message — semantic model: turns a message/enum token block into a typed object with fields

**Pipeline role:** Front-end, stage ~2–3 (semantic analysis). Consumed by `MessageCreator` (LexicalAnalizer) to build the intermediate representation the back-end `FileCreator` renders into proto/C++.
**Entry points:**
- `Message(fileName, availableMessages, md5Hash).Process(tokens)` → `None` or `Error`; called by `MessageCreator.CreateMessages`.
- Internally `Message.Process` constructs `Variables(...)` or `EnumValues(...)` and calls their `.Process()` then `.get()`.
**Inputs → Outputs:** a slice of tokens for one `message {...}`/`enum {...}` block → a `Message` with `.name`, `.variables` (list of `variable` or `(name,int)` enum tuples), `.access_modifiers`, `.tableName`, `.visibility`, `.isEnum`, `.dependency`.

## Files
- `Message.py` — `Message`: scans the block. Reads access modifiers (tokens between the preceding NEWLINE — or the start of the slice, when the message is the first thing in the token stream — and the `message` keyword) e.g. `pull`/`event`/`stream` → sets `isOneToMany`; `critical` → sets `is_critical` (sensitive-data roadmap Phase 1a — message-type criticality axis, design-rules §0, independent of any field's `is_phi`; dedicated bool so later stages read it instead of re-scanning `access_modifiers`; flag only, the delivery-guarantee machinery is roadmap Phase 3). Name = ID token after `message`/`enum`. Between `{` and `}` delegates to `Variables` (message) or `EnumValues` (enum). For a non-enum message, immediately after `Variables.get()` it calls `FieldMap.freeze()` to overwrite the declaration-order indices with the frozen ones (or propagate its `Error`) — see `FieldMap.py` below. After `}`: a trailing `;` sets `visibility=PRIVATE`; a trailing ID sets `tableName`. `dependency` = composed-field type names.
- `Variables.py` — `variable` (POD: index, name, type tuple, regex, modifiers, typeMap, paginationSize, repeteableSize, constant, renamedFrom, `is_phi`) and `Variables` (the field parser). Splits fields on `;`, detects modifiers `repeteable[N]`/`optional`/`unique`/`required`/`renamed_from[old]`/`pagination[N]`/`map<...>`/`phi` (Foundation F2 — the confidentiality-axis sensitive-field tag, see `Initiatives/medical_devices/harpia_sensitive_data_design_rules.md` §0; parsed the same way as `optional`/`unique`/`required` — a keyword-only modifier appended to `modifiers`, plus the dedicated `is_phi` boolean flag the plan calls for so later stages don't have to re-scan `modifiers` themselves), resolves type (scalar INT32/INT64/FLOAT/STRING, `map`, or a composed message name from `composedVariables`), and derives a validation regex. Assigns a **provisional** `index = len(variables)+1` (declaration order) — `Message.Process` immediately overwrites this via `FieldMap.freeze()`, so declaration order only matters for a field's number on the very first generation.
- `EnumValues.py` — `EnumValues`: two passes. First collects explicit `NAME = N;` values, sorts them, computes next free value; second pass assigns auto values to bare `NAME;` entries. Enforces unique values via `allUnique()`. Accepts 2-token (`NAME;`) or 4-token (`NAME = N;`) forms; each value must start its line. Not covered by `FieldMap` — enum member values are a separate numbering space from message field wire numbers, and are not (yet) frozen the same way.
- `FieldMap.py` — **stable wire-number field identity**, shipped as part of the message-versioning effort's foundation (2026-08-22). `freeze(variables, harpiaFile, messageName)` reads/writes a plain-text sidecar (`registry_path()`: `<dir of harpiaFile>/schema_registry/<harpiaFile stem>/<messageName>.fieldmap`, one `name:number` line per field plus an optional trailing `# reserved: 4,7` line) and reassigns each `variable.index` in place from it instead of from declaration order — the direct fix for the hazard in the bullet below. First generation for a message (no sidecar yet) just freezes the declaration order as-is. Later generations: a field keeps its old number if its name (or, for hidden fields, its *role* — see next bullet) is already in the sidecar; `renamed_from[old]` inherits `old`'s number if `old` is on record (a no-op fallback to plain new-field numbering otherwise, mirroring `Database/MigrationAdapter`'s own conditional RENAME); a name dropped from the sidecar is retired into `reserved`; a genuinely new field gets the lowest number never used live or retired. Returns `Error(RESERVED_FIELD_NUMBER_REUSED)` if a resolved number ever lands on a reserved one (only reachable via a hand-tampered sidecar today, since the DSL has no `field = N` syntax to trigger it directly) — a hard generation-time error, per the "never silently swallow a failure mode" convention `harpia_sensitive_data_design_rules.md` Rule 5 also uses.

## Key facts / gotchas
- **md5 hash drives hidden field names.** `Variables.__init__` auto-prepends `ID_<md5>` and `AddHiddenVariables` appends `STATUS_<md5>`, `ERROR_<md5>`, and `ORIGINATOR` (named `ORIGINATOR_<md5>` only when `isOneToMany`). Because `main.py` passes the ROOT file's md5 for every message, all messages across all imported files share the same hash suffix — a collision risk for the upcoming multi-root-file feature (two roots ⇒ different hashes; same root imported twice ⇒ identical suffixes). **This also means a hidden field's literal name changes on ANY edit to the `.harpia` file** (the md5 is over the whole file text) — `FieldMap` accounts for this by keying these four fields by role (`ID`/`STATUS`/`ERROR`/`ORIGINATOR`, matching `Database/model.py`'s own `_HIDDEN_PREFIXES` convention) rather than by literal name, so their wire numbers stay stable across hash changes the same way user fields' do.
- Composed (message-typed) fields: if `var.type[1] in composedVariables`, regex is set to the type itself and the type name is added to `self.dependencies` (1-to-many via link table when `repeteable`).
- **`phi` is flag-only *in the front end* (F2's stated scope).** `FileCreator.Process()` never inspects `is_phi`/`"PHI" in modifiers`, so a `phi` field emits byte-for-byte the same `.proto` line as the same field without `phi`. Downstream tracks are what read `variable.is_phi`: **Track A** (`Database/CrudlAdapter.py` — envelope-encrypt/decrypt + audit on the DAO path) and **Track F / F.3** (`SerializeAdapter.py` — emits `serialize/harpia_phi_registry.h`, the `(message, field)` phi table the unified `toString` façade uses to render every `phi` value as `[REDACTED]` in JSON/XML/YAML). This module only makes the tag available on the AST.
- **`critical` is flag-only too (sensitive-data roadmap Phase 1a).** `Message.is_critical` is set from the `CRITICAL` token in `access_modifiers`; no adapter reads it yet, so a `critical` message emits byte-identical `.proto`/DB/JSON/… to the same message without it. The `ORIGINATOR`-suffix behaviour it looks adjacent to is driven by `isOneToMany` (`event`/`stream`/`pull`), NOT by `critical` — `critical` composes with those but doesn't imply any of them. The bounded rotating queue / 2-slot mailbox this gates is roadmap Phase 3 (a transport-agnostic generated runtime + `ZmqAdapter` wiring).
- **Mutable class-attribute bug in `EnumValues`:** `values = []` is a class attribute and `createValues` appends to it, so enum values can leak across `EnumValues` instances. `Variables`/`Message` mostly re-init lists in `__init__` (safer), but `Message`'s class-level defaults (`variables=None` etc.) are shadowed per-instance.
- `type` is stored as the raw token tuple `(TYPE, lexeme, line, col)`; downstream code reads `var.type[0]`/`[1]`.
- Regex constants live on `Variables` (RegexForInt/Float/String); `map` regex via `RegexForMaps`.
- **`schema_registry/` sidecars are a local file, not build output, and not committed** — they live next to the `.harpia` file (e.g. `HarpiaTest/schema_registry/`), deliberately outside whatever `dest`/`HARPIA_OUTPUT_DIR` points at, because that build dir gets `rmtree`d/regenerated wholesale (see `UnitTests/run_pipeline.py`). Project policy is **git-ignored repo-wide** (`.gitignore`: `schema_registry/`): the sidecar is regenerated per checkout, not tracked. Within one working tree it still freezes wire numbers across regenerations. Don't hand-edit; a message's field additions/removals/renames update it automatically on the next generation.

## Touchpoints

- Depends on: `Errors.Error`, `Logger.logger`, `uuid`, `Util.util.write_if_different` (via `FieldMap`). Consumed by back-end `FileCreator` (reads `variable.index` for the `.proto` field number).
